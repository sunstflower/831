# 无人物流调度管理软件设计文档

## 1. 设计目标

本系统面向园区、仓储、校园等中小规模场景，目标是用统一的桌面化管理界面完成任务创建、车辆调度、路径规划、执行监控和异常处理。

设计原则如下：

1. 先保证业务闭环，再追求算法最优。
2. 先保证可观察、可回放，再追求高自动化。
3. 先保证本地可稳定运行，再扩展云端能力。
4. 业务逻辑、算法逻辑、存储逻辑、UI 逻辑必须解耦。

## 2. 总体架构

### 2.1 分层

1. 展示层：React 页面、地图、表格、图表、弹窗。
2. 状态层：全局状态、页面状态、筛选条件、临时编辑态。
3. 业务层：任务、车辆、调度、路径、告警、统计、权限。
4. 算法层：A*、Dijkstra、贪心、匈牙利、遗传算法。
5. 数据层：SQLite、查询仓库、迁移脚本、审计日志。

### 2.2 运行形态

- 桌面端应用：Electron 主进程负责窗口、文件、数据库、系统能力。
- 渲染进程：React 负责交互、视图和局部状态。
- 内部通信：通过 IPC 或统一服务适配层完成数据交互。

## 3. 模块设计

### 3.1 登录与权限模块

目标：

- 提供基础登录、退出和会话管理。
- 区分调度员、管理员、监控员等角色。
- 限制敏感操作范围。

职责：

- 账号认证
- 角色鉴权
- 路由与按钮级权限控制
- 操作审计标识

验收：

- 未登录不可进入业务页。
- 无权限用户看不到对应操作入口。

### 3.2 基础数据模块

目标：

- 维护站点、车辆、路网、任务模板等基础数据。
- 为调度和路径计算提供稳定输入。

职责：

- 站点增删改查
- 车辆增删改查
- 节点/边/禁行规则维护
- 模板化默认参数维护

验收：

- 基础数据可持久化并可随时查询。
- 数据变更后能即时影响调度候选集。

### 3.3 任务管理模块

目标：

- 完成任务从创建到结束的全生命周期管理。

职责：

- 单任务创建
- 批量导入
- 编辑、暂停、取消、恢复、重派
- 任务状态机维护

任务状态建议：

- `draft`
- `pending`
- `assigned`
- `running`
- `finished`
- `cancelled`
- `failed`

验收：

- 每个任务状态迁移有明确前置条件。
- 非法状态迁移必须被拒绝。

### 3.4 调度引擎模块

目标：

- 在约束条件下为任务匹配最合适车辆，并生成可执行计划。

职责：

- 候选车辆筛选
- 代价函数计算
- 算法策略切换
- 多车并发分配
- 冲突检测与重算

约束范围：

- 时间窗
- 载重
- 车辆状态
- 车辆位置
- 区域/路段通行限制
- 任务优先级

验收：

- 同一批任务可输出多个策略结果用于对比。
- 约束不满足时要给出明确拒绝原因。

### 3.5 路径规划模块

目标：

- 为单车、单任务或多任务计划生成可执行路线。

职责：

- 图建模
- 最短路计算
- 禁行规避
- 路径回显

算法要求：

- A* 用于带启发式的快速搜索。
- Dijkstra 用于稳定的最短路基线。
- 所有路径结果必须可解释、可复核。

验收：

- 每条路线可展示起点、终点、经过节点、总距离、预计耗时。

### 3.6 地图可视化模块

目标：

- 把任务、车辆、站点、路径、告警直观展示在同一空间视图中。

职责：

- 地图渲染
- 图层控制
- 车辆定位
- 路线高亮
- 实时刷新

验收：

- 页面能在列表、地图、详情间快速联动。

### 3.7 运行监控模块

目标：

- 持续展示车辆运行、任务执行和异常状态。

职责：

- 状态刷新
- 进度跟踪
- 异常提示
- 手动接管入口

验收：

- 关键状态变化可在监控页及时看见。

### 3.8 告警模块

目标：

- 对异常事件进行归类、提示和留痕。

职责：

- 告警生成
- 告警确认
- 告警处理
- 告警归档

告警类型：

- 车辆离线
- 任务超时
- 任务失败
- 路径阻断
- 数据异常

验收：

- 告警必须有来源、级别、时间、对象、状态。

### 3.9 统计分析模块

目标：

- 让运营方能看见系统效率与瓶颈。

职责：

- 完成率统计
- 利用率统计
- 响应时长统计
- 异常率统计
- 多维筛选

验收：

- 统计口径一致，可复算。

### 3.10 审计与日志模块

目标：

- 记录所有关键行为，方便追责和排查。

职责：

- 操作日志
- 调度日志
- 异常日志
- 数据变更日志

验收：

- 关键操作必须可追踪到执行人、时间、对象和结果。

### 3.11 系统设置模块

目标：

- 管理全局参数和默认运行策略。

职责：

- 调度默认策略
- 路径算法偏好
- 超时阈值
- 刷新间隔
- 主题和显示偏好

验收：

- 设置项可保存并在下次启动生效。

## 4. 设计规范

### 4.1 命名规范

- 组件使用 PascalCase。
- 变量、函数、接口字段使用 camelCase。
- 常量使用 UPPER_SNAKE_CASE。
- 状态枚举使用语义化英文小写字符串。

### 4.2 数据规范

- 时间统一使用 ISO 8601。
- 坐标统一使用 `{ x, y }` 或 `{ lng, lat }`，同一模块内不能混用。
- ID 统一使用字符串型主键。
- 数值单位必须明确：距离、时长、载重、电量分别固定单位。

### 4.3 状态规范

- 任何状态变化都要经过显式校验。
- 页面态和业务态分离。
- 算法输出态不得直接污染原始业务数据。

### 4.4 错误规范

- 统一错误结构。
- 错误必须包含 code、message、source、detail。
- 业务错误与系统错误分开处理。

### 4.5 日志规范

- 记录时间、操作者、模块、对象、结果、耗时。
- 调度结果和重算结果必须留痕。

## 5. 交互原则

1. 常用操作放在一级入口。
2. 列表、地图、详情三者联动。
3. 高风险操作必须二次确认。
4. 算法结果先预览后生效。
5. 异常处理必须给出明确下一步。

## 6. 首期范围

首期仅保留以下模块：

- 登录与权限
- 基础数据
- 任务管理
- 调度引擎
- 路径规划
- 地图可视化
- 运行监控
- 告警
- 审计日志
- 系统设置

首期不做：

- 真实设备协议接入
- 云端同步
- 多租户
- 复杂权限矩阵
- 大规模分布式优化
